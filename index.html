Cloud PM · Data Analytics · Full-Stack

MigrationOps — Cloud Service Deprecation Analytics Platform

What This Is

A full-stack analytics platform simulating an enterprise cloud service deprecation and customer migration program — built for Azure Data PM portfolio context. Demonstrates the skill set a PM needs when managing large-scale customer migrations away from a deprecated service.

Four Core Pages

  • Main Dashboard — 8 KPI cards: total users, deprecated-version count, migration rate, high-churn-risk users, and more. Includes 90-day DAU time series, version distribution donut, migration funnel, error rate trends, regional breakdown, and churn risk matrix.
  • User Explorer — Filterable, paginated table of 2,000 simulated users by version (v1/v2/v3), region (US-East, EU-West, APAC), tier (Enterprise → Free), and churn risk. Exportable as CSV — the exact tool a CSM or PM uses for outreach queues.
  • Telemetry & Events — ~70,000 API call event log with error detection and latency tracking. Daily active users by version, usage segmentation, and anomaly detection — showing KQL-style telemetry thinking.
  • Migration Strategy & PRD — Full internal PM doc: P0–P3 priority framework, 4-phase migration timeline, 4-touchpoint comms plan, 7 KPI definitions with formulas, 5 SQL scripts, 5 KQL queries. PDF-exportable.

PM Skills Demonstrated

  • SQL analytics — churn scoring, user segmentation, migration funnel queries
  • KQL / Azure telemetry — DAU trends, error spikes, latency percentiles, version rollout
  • Churn risk composite scoring (0–100) with P0–P3 segment prioritization
  • 4-phase migration plan, escalation playbook, and automation roadmap

Azure PM Tool · KQL · T-SQL · Migration Dashboard

Azure Synapse → Microsoft Fabric Migration Tracker

What This Is

A PM-built tool for tracking enterprise customer migrations from deprecated Azure Synapse Analytics to Microsoft Fabric. Simulates the exact tooling and decisions needed during a large-scale platform deprecation — covering telemetry-driven customer identification, urgency segmentation, outreach automation, and a live migration dashboard.

Key Features

  • Telemetry-Driven Customer Identification — KQL queries against Azure Monitor / AzureDiagnostics to surface customers actively using deprecated Synapse features and flag at-risk accounts before they churn.
  • SQL Urgency Segmentation — T-SQL queries segmenting customers into CRITICAL / HIGH / MEDIUM / LOW migration tiers based on dependency depth, usage frequency, and account tier.
  • 6-Step Deprecation Playbook — Detection → Segmentation → Outreach → Migration Support → Validation → Completion, with owner assignments and SLAs at each step.
  • Customer Outreach Queue — Personalised outreach emails generated from telemetry data, pre-populated with account details and recommended next steps — ready for CSM or PM use.
  • Migration Progress Dashboard — Live Chart.js charts showing migration status by region and customer tier, tracking progress toward full Synapse deprecation.

PM Lens

  • Shows clear understanding of Azure's deprecation lifecycle and what a Data PM does at Microsoft
  • Combines data signals (telemetry) with product action (outreach, playbook) — not just dashboards
  • SQL + KQL fluency grounded in customer impact, not just technical depth

Logistics · Product Strategy · UX Research

The Last 100 Meters: Recovering 1.7M Hours of Annual Fleet Capacity

Problem Statement

Hyperlocal delivery operations suffer from a critical inefficiency at the final 100 meters. The "Manual Stasis" loop — where delivery agents wait, re-attempt, and fail due to unclear addresses and unavailable customers — wastes millions of hours annually in fleet capacity.

My Approach

Analyzed end-to-end delivery workflows through user journey mapping, identifying the exact breakdown points between dispatcher, delivery agent, and end customer.

Key Insights

  • Final 100m accounts for disproportionate delivery failure — not route length, but last-step friction
  • Agents lacked real-time customer availability signals, leading to preventable re-attempts
  • Address standardization and predictive scheduling could reclaim 1.7M+ annual hours of fleet time

Proposed Solution

A smart last-mile module with real-time customer availability pings, geo-fenced precise drop-off zones, agent-side micro-routing, and a feedback loop feeding into dynamic scheduling.

EV Ecosystem · Market Strategy · Retention

Ola Electric: Bridging the Service-Experience Gap

Problem Statement

Ola Electric customers face high post-purchase anxiety driven by opaque vehicle diagnostics, poor service transparency, and a weak support ecosystem — causing churn despite a strong product.

My Approach

Conducted a market teardown of Ola Electric's post-purchase experience, mapping it against EV industry benchmarks and customer review data. Identified "Service Anxiety" as the core retention killer.

Key Insights

  • Vehicle diagnostics are opaque — users have no visibility into what's wrong or when to service
  • Service centre experience is fragmented from the app — no integrated end-to-end digital journey
  • A transparent, app-integrated service layer would significantly improve NPS and retention

Proposed Solution

An in-app Vehicle Health Dashboard with real-time diagnostics, service appointment management, transparent progress tracking, and proactive alerts.
